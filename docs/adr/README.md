# 아키텍처 결정 현황판 (ADR Board)

**이 표가 현재 유효한 전역 결정의 전부다** — 히스토리가 아니라 현황.
"우리 X를 왜 이렇게 하지?"는 여기서 시작한다: 표에서 영역을 찾고, 링크된
ADR에서 근거·탈락안·경위를 읽는다. **대체된 결정은 이 표에 없다** (해당 ADR
파일의 상태 필드와 대체 링크로만 남는다) — 표를 읽는 사람은 이력을 따라갈
필요 없이 현재만 본다.

## 현황

| 영역 | 현재 접근 | 한 줄 근거 | ADR | 결정일 |
|------|----------|-----------|-----|--------|
| _(아직 없음 — 첫 전역 결정에서 시작)_ | | | | |

## 규칙

- **승격 시점**: 7단계 통과(결정 로그 최종화) 시 즉시 — 그 기능의 설계에 전역
  영향 결정(솔루션 접근, 아키텍처 패턴, 정합성/동시성 전략, 인증 모델, 데이터
  모델 경계)이 있으면 그 자리에서 승격한다 (team-policy §전역 결정 기록).
  주기 감사는 누락을 잡는 백스톱이지 기본 경로가 아니다.
- **같은 커밋 규칙**: ADR 파일 추가/대체와 이 현황판 갱신은 **같은 커밋**으로.
  현황판에 없는 ADR은 없는 결정이다.
- **ADR 본문은 append-only**: `docs/adr/NNN-<slug>.md`의 본문은 고쳐 쓰지
  않는다. 유일한 예외는 **상태 필드 갱신**(`채택` → `대체됨 → NNN`) — 결정이
  바뀌면 새 ADR을 만들고 옛 것의 상태만 바꾸며, 현황판의 해당 행을 새 ADR로
  교체한다.
- **번호(NNN)는 머지 시점 현황판 기준 최댓값+1**로 확정한다 — 병렬 브랜치가
  같은 번호를 선점했으면 나중에 머지되는 쪽이 리넘버한다.
- **내용은 복제가 아니라 승격**: 근거·대안은 설계 문서(§0-2 비교표)와 결정
  로그에 이미 있다 — ADR은 그걸 전역 관점으로 요약하고 원본을 링크한다.

## ADR 파일 형식

```markdown
# NNN: <결정 한 줄>

- 상태: 채택 | 대체됨 → NNN
- 날짜: YYYY-MM-DD
- 출처: <feature-name> — 결정 로그(.agents/context/decisions/<feature>.md) +
  설계 문서 §0-2

## 결정
[무엇을 어떻게 하기로 했는지]

## 근거와 탈락안
[설계 문서의 접근 비교표 요약 또는 원문 — 탈락안과 탈락 사유 포함]

## 파생 요구사항
[R-D# 목록 — 이 결정이 시스템에 지운 의무. 없으면 "없음"]
```
