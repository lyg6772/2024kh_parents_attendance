## [1단계] 기획 분석 산출물 (완결성 비평가 반영 완료)

### 입력
- 요구사항: 대화 입력 (기획 문서 파일 없음 → §2-2 충실도 비평가는 N/A)
- 0단계 산출물: `00-codebase-discovery.md`

### 배경 — 왜 이 기능이 존재하나

`osv-scanner.toml` 에 CVE 74행 / 13개 패키지가 기준선으로 등재돼 있고, 그 파일이
해소 순서를 이미 적어 두었다: **① 오라클을 만든다 → ② 올린다 → ③ 등재를 지운다.**
지금 앱 테스트 242개는 전부 순수 유닛이라 취약 패키지를 하나도 실행하지 않는다.
그래서 지금 버전을 올리고 초록을 보면 **그 초록은 아무것도 증명하지 않는다.**
이번 작업은 ① 이고, ②는 범위 밖이다.

### 기능 요구사항

| ID | 요구사항 | 왜 필요한가 |
|---|---|---|
| FR-1 | HTTP 요청이 실제 ASGI 스택을 통과하는 테스트가 있다 | h11(HTTP 파서)·python-multipart(폼)·jinja2(SSR)를 실행 경로에 올리는 유일한 방법 |
| FR-2 | 인증 경로(토큰 발급·검증·거부)를 검증하는 테스트가 있다 | pyjwt·cryptography 를 실행 경로에 올린다. 현재 `encode_token`·`decode_token`·`get_current_user` 는 커버하는 테스트가 0이다 (codegraph 확인) |
| FR-3 | 인증이 걸린 라우트가 **토큰 없이는 거부**되고 **유효 토큰으로는 통과**하는 것을 검증한다 | 통과만 검증하면 인가 경계가 사라져도 초록이다. 대상 라우트 목록은 4단계에서 실행으로 뽑는다 (A-4) |
| FR-4 | 테스트가 **개발자 `.env` 값에 의존하지 않는다** | 그 파일은 gitignore 대상이라 클론마다 값이 다르거나 없다. 오라클이 머신마다 다른 값을 쓰면 실패가 재현되지 않는다 |
| FR-6 | 인가 모델이 이진임을 검증한다 — 토큰 = 관리자, 무토큰 = 조회 전용 | 사람 확인 2026-08-02: 의도된 설계다. 코드로 확인함 — `KY_USER_L` 에 역할 컬럼이 없고(`user_id`/`user_pw` 뿐) `/attendee` 계열은 인증을 안 건다. 즉 **토큰 소지 자체가 관리자 자격**이다 |
| FR-5 | 테스트가 실 DB 에 접속하지 않는다 | `DB` 싱글턴이 Oracle/MySQL 로 붙는다. 테스트가 실 인프라를 요구하면 CI 에 못 올린다 |

### 제약조건

| ID | 제약 | 출처 |
|---|---|---|
| C-1 | 앱 코드(`app/`)를 수정하지 않는다 | 이번 범위는 오라클 생성이다. 앱 수정은 오라클이 생긴 뒤 판단할 일 |
| C-2 | 의존성을 추가하지 않는다 | `httpx 0.27.2` 가 이미 설치돼 있음을 확인했다. 추가하면 설계 게이트 대상이 된다 |
| C-3 | 기존 테스트 6개 파일 242개를 깨뜨리지 않는다 | 회귀 금지 |
| C-4 | 테스트는 레포 루트에서 실행된다 | Jinja2 템플릿 경로가 상대경로다 (`./app/template`, `./template`) |

### 수용 기준 (검증 가능한 형태로)

| ID | 기준 | 어떻게 확인하나 |
|---|---|---|
| AC-1 | 테스트 실행 중 `config.SECRET_SALT` 와 `config.DB_URL` 이 **conftest 가 세운 목 값과 같다** | 그 값을 직접 단언하는 테스트를 둔다. 개발자 `.env` 가 무엇이든 같은 값이 관측되어야 한다 |
| AC-2 | 인증 필수 라우트 각각에 대해, 토큰 없는 요청이 보호 리소스를 반환하지 않는다 | 응답이 `/login` 리다이렉트임을 확인 (401 이 아니다 — `app/main.py` 401 핸들러). **라우트 수는 4단계에서 실측해 확정한다** — 초안의 "6개"는 검증되지 않은 값이었다 |
| AC-7 | 토큰 **없이** `/attendee` 계열은 정상 조회된다 | 이진 인가 모델(FR-6)의 반대편. 이쪽까지 봐야 "무토큰이면 다 막힌다"는 오독을 막는다 |
| AC-3 | 유효 토큰을 실은 요청은 해당 엔드포인트의 정상 응답을 받는다 | 상태 코드 + 응답 본문/헤더 |
| AC-4 | 만료된 토큰과 위조된 토큰이 각각 거부된다 | `AuthHandler` 로 만료 토큰을 만들고, salt 를 바꿔 서명한 토큰을 만든다 |
| AC-5 | 새 테스트가 취약 패키지를 실제로 실행한다 — **프레임으로 관측한다** | ASGITransport: jinja2 · starlette · pyjwt · python-multipart. 실소켓: h11. **cryptography 는 뺐다** — 2단계 실측에서 이 앱에 실행 경로가 없음이 드러났다(HS256=stdlib `hmac`, 비번=`bcrypt` 패키지). 초안이 5종이라고 쓴 것은 검증 없는 주장이었다 |
| AC-9 | `GET /admin/attendee/export/{yyyymm}` 이 엑셀 스트림을 반환한다 | 실사용 경로다(프론트의 유일한 export 호출). openpyxl·StreamingResponse 경로를 덮는다 |
| AC-6 | 테스트가 2회 연속 같은 결과를 낸다 | 4단계 결정성 게이트 |
| AC-8 | 테스트가 외부 LLM 을 호출하지 않는다 | `GROQ_API_KEY`·`GEMINI_API_KEY` 를 빈 값으로 세우고, `/agent/chat` 이 `status: "error"` 를 내는 것을 확인 |

### 범위 밖 (non-goals)

| 무엇 | 왜 |
|---|---|
| 의존성 버전 업그레이드 | 사람 판정 — 오라클과 한 PR 에 묶으면 red 원인이 갈린다 |
| `osv-scanner.toml` 등재 제거 | ②·③ 단계. 이번이 아니다 |
| `pymysql` 커버리지 | 테스트가 SQLite 를 쓰므로 구조적으로 못 덮는다. 알려진 한계로 7단계까지 끌고 간다 |
| `GET /admin/attendee/export` — **날짜 없는 변형만** | 도달 불가한 등록이다. `router.py:15` 의 `{cal_date}` 가 `:16` 보다 먼저 등록돼 `cal_date="export"` 로 매칭된다. **실결함이 아니다** — 이 경로를 부르는 곳이 레포에 없다(유일한 호출자는 `app/template/admin_attendee.html:708` 의 날짜 있는 경로). 죽은 등록 + 컨트롤러의 `if not cal_date` 죽은 분기이므로 후속 과제로 적고 오라클에서는 뺀다 |
| `.env` **파일 부재** 자체의 재현 | 사람 판정: conftest 강제 덮어쓰기로 간다. 파일이 없는 상태를 직접 재현하지는 않는다 — 그건 클론·CI 의 일이고 이 레포엔 CI 가 없다 |
| Jinja2 템플릿 경로 불일치 수정 | 앱 코드 변경 (C-1) |
| 로그인 쿠키에 `secure=True` 누락 | 0단계에서 관측됐으나 앱 코드 변경이고 요구에 없다 — 후속 과제 |
| `test_engine.py`·`test_failover.py` 의 기존 `.env` 의존 | FR-4 를 만족시키면 딸려 풀린다. **고치는 것이 목적이 아니다** |

### 가정 대장 (요구에 없는데 내가 정한 것)

| # | 가정 | 다른 해석 | 왜 이쪽인가 |
|---|---|---|---|
| A-1 | 목 `SECRET_SALT` 는 고정 문자열이다 | 매 실행 랜덤 생성 | JWT 검증은 알려진 salt 가 있어야 재현된다. 랜덤이면 실패를 재현 못 한다 |
| A-2 | 목 환경값이 개발자 `.env` 를 **덮는다** | `.env` 가 있으면 그쪽 우선 | 테스트가 개발자 비밀에 의존하면 사람마다 결과가 갈린다. `load_dotenv(override=False)` 라 conftest 가 먼저 세우면 자동으로 이렇게 된다 |
| A-3 | DB 는 in-memory SQLite | 파일 SQLite / 테스트 컨테이너 | 기존 `conftest.db_session` 이 이미 in-memory 다. 재활용이 신규보다 싸고 일관된다 |
| A-4 | 라우트를 전부 훑는다. **개수는 4단계에서 실측해 확정한다** | 인증 걸린 것만 | 취약 패키지 실행이 목적이라 SSR·엑셀 경로도 필요하다. 깊이는 얕게 — 오라클이지 기능 테스트가 아니다. 초안의 "11개/6개"는 손으로 센 값이라 비평가가 12/7 로 반박했다. **숫자는 문서가 아니라 실행이 소유한다** |
| A-5 | 테스트는 LLM 키를 빈 값으로 세워 외부 호출 경로를 죽인다 | 실호출 허용 / 어댑터 몽키패치 | 비평가 검증 중 **개발자 키로 실제 Groq 호출이 나갔다**(실측). 오라클이 유료·비결정 외부 호출을 하면 안 된다 — 물을 여지가 없어 가정으로 내린다 |
| A-6 | 날짜 인자가 고정된 경로를 기본 검증에 쓴다 | 현재 월 경로를 그대로 | 인자 없는 경로는 UTC 현재 월에 의존해 월경계에서 흔들린다. 인자 없는 경로는 상태 코드만 본다 |
| A-7 | fixture teardown 에서 `dependency_overrides.clear()` + 몽키패치 복원 | 안 함 | C-3(기존 242개 회귀 금지)이 이미 요구하는 바다 |

## 사람 판정 (2026-08-02)

비평가가 승격한 3건에 대한 응답이다.

1. **`.env` 관측** → conftest 가 목 값으로 **강제 덮어쓴다.** 파일 부재 자체를 재현하지
   않는다. AC-1 을 "그 명령이 통과한다"에서 "관측되는 값이 목 값과 같다"로 바꿨다 —
   초안의 AC-1 은 무효였다(아래 § 초안의 사실 오류 참조).
2. **`/admin/attendee/export`** → 제외 + 후속 과제. 앱을 고치지 않는다(C-1 유지).
3. **admin 역할 검사** → **공백이 아니라 의도된 설계다.** 토큰은 로그인 이후에만
   발급되고, 토큰 없으면 조회만 된다. 코드로 확인함: `KY_USER_L` 에 역할 컬럼이 없고
   (`user_id`/`user_pw` 뿐) `/attendee` 계열은 인증을 안 건다. 그래서 이것은 한계가
   아니라 **검증 대상**이 되어 FR-6·AC-7 로 올라갔다.
   - 이 설계가 기대는 불변식을 명시해 둔다: **`KY_USER_L` 에 관리자만 들어간다.**
     코드가 아니라 데이터가 지키는 성질이므로, 비관리자가 그 테이블에 들어가면 그
     순간 관리자가 된다. 이번 범위에서 고칠 것은 아니고, 설계가 무엇에 기대는지를
     적어 두는 것이다.

## 초안의 사실 오류 (비평가가 실측으로 반박, 정정함)

- **"`env -u SECRET_SALT -u DB_URL pytest tests` 는 지금 red"** → **틀렸다. 242 passed 다.**
  내가 그 값을 잰 것은 **다른 cwd** 에서였고, `config.py` 는 `os.getcwd()/app/.env` 를
  읽으므로 실제 변수는 환경변수가 아니라 **cwd** 였다. 레포 루트에서는 `.env` 가 그대로
  읽혀 값이 되메워진다(`load_dotenv` 는 기본 `override=False`).
- **"엔드포인트 11개 / 인증 6개"** → 손으로 센 값이고 비평가는 12/7 을 제시했다. 어느
  쪽도 지금 확정하지 않는다 — 4단계에서 라우트 표를 **실행으로 뽑아** 쓴다.
- **"`get_session` 오버라이드로 DB 를 격리한다"**(0단계 판정) → **틀렸다.** DAO 3개 파일이
  `Depends(DB().get_db_session)` 를 쓴다. `get_session` 은 에이전트 라우터 2곳뿐이다.
  DB 배선은 3단계 §0-2 접근 결정으로 이월한다.
