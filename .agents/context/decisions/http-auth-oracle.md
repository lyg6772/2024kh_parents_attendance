# 결정 로그 — http-auth-oracle

브랜치: `feat/http-auth-oracle`
목적: HTTP·인증 경로에 통합 테스트를 만들어 **의존성 업그레이드의 오라클을 세운다.**
`osv-scanner.toml` 이 적어 둔 해소 순서 ① 이다.

## 0단계 — 코드베이스 탐색 (2026-08-02)

산출물: `.agents/context/artifacts/http-auth-oracle/00-codebase-discovery.md`

### 사람 판정

- **범위는 오라클까지, 업그레이드는 이번에 안 한다.** 한 PR 에 묶으면 red 가
  "테스트가 틀렸나 / 업그레이드가 깼나"로 갈리는데, 지금은 기준선이 없어 그 구분이
  불가능하다. 오라클이 먼저 서야 업그레이드가 검증 가능해진다.
- **파이프라인을 설계대로(서브에이전트 포함) 돌린다.** 이번 실행의 목적 자체가
  하네스를 실측하는 것이라, 크리틱·감사·뮤테이션·리뷰를 직접 대신하면 그 목적이 사라진다.

### 탐색으로 확정한 것

- 엔드포인트 11개(컨트롤러 9 + 에이전트 2), 이 중 **6개가 인증을 건다**.
- 앱 테스트 242개는 **전부 순수 유닛**. codegraph 가 `encode_token`·`decode_token`·
  `get_current_user`·`login_post` 를 모두 "no covering tests found" 로 보고했다.
- `httpx 0.27.2` 가 이미 설치돼 있다 → **의존성 추가 없이** ASGI 를 탈 수 있다.
  이것이 설계 게이트 조건(의존성 추가) 하나를 미리 지운다.
- `tests/conftest.py` 의 `db_session` 을 그대로 재활용한다.

### 실행으로 확인한 제약 (추론 아님)

1. `app/config.py` 는 `SECRET_SALT` 없으면 import 시점에 `RuntimeError`. `app/.env` 는
   `.gitignore` 대상이라 새 클론·CI 에 없다 → 오라클은 앱 import 전에 환경을 세워야 한다.
   지금 로컬이 초록인 것은 개발자 머신에 `.env` 가 있어서일 뿐이다.
2. `app.main` 은 import 시점에 `DB().init_db()` 를 부른다 → sqlite `DB_URL` 도 함께 필요.
   `SECRET_SALT=x DB_URL=sqlite+aiosqlite:///:memory:` 로 import 성공, 라우트 17개.
3. 401 은 예외가 아니라 `/login` **리다이렉트**로 관찰된다 (`app/main.py` 의 401 핸들러).
   수용 기준을 "401 을 받는다"로 쓰면 앱이 아니라 내 기대를 검증하게 된다.
4. Jinja2 템플릿 경로가 파일마다 다르다 (`./app/template` vs `./template`) — 범위 밖,
   2단계 영향 맵에 올린다.

### 알려진 한계 (지금 정해 두고 7단계까지 끌고 간다)

- `pymysql` 은 이번 오라클로 **안 덮인다.** 테스트가 in-memory SQLite 를 쓰므로 MySQL
  드라이버를 타지 않는다. 나머지 다섯(h11 · python-multipart · pyjwt · cryptography ·
  jinja2)은 실행 경로에 오른다.
- CVE 등재 현황 실측: **74행 / 13개 패키지** (`grep -c IgnoredVulns osv-scanner.toml`).
  문서 산문의 "6개"는 실사용 경로 위만 센 값이다.

### 0단계 보정 (사람 지적으로 바로잡음)

처음에 나는 ".env 의존이 이번 작업이 만드는 새 제약"인 것처럼 적고, 그것을 1단계
수용 기준으로 올리자고 제안했다. **틀렸다 — 이미 있는 결함이고, 그 제안은 범위
확장이었다** (규칙 5). 실측:

| 조건 | 결과 |
|---|---|
| `.env` 없음, 환경변수 없음 | 213 collected, **2 errors** (`test_engine.py`, `test_failover.py`) |
| `.env` 없음, 목 값 두 개만 | **242 collected → 242 passed** |

목 값은 `SECRET_SALT` 와 `DB_URL` 둘뿐이다. 그리고 안전하다 — 두 파일은
`app.agent.llm` 을 import 만 하고 키 값을 읽지 않는다 (`get_llm()` 호출 0,
`api_key` 참조 0). 죽던 이유는 키가 필요해서가 아니라 import 사슬이 `config` 를
지나가기 때문이다.

**결정**: `tests/conftest.py` 가 앱 import 전에 목 환경을 세운다. 앱 코드는 안 건드린다.
기존 2건이 함께 풀리는 것은 고친 것이 아니라 딸려오는 결과이므로, 이번 범위를 넓히지
않는다.

**부작용을 하나 의도적으로 받는다**: `load_dotenv` 는 기본이 `override=False` 라
conftest 가 먼저 세우면 개발자의 `.env` 가 이를 못 덮는다. 즉 테스트는 항상 목 값을
쓴다. 이것이 오히려 옳다 — JWT 검증은 **알려진 salt** 가 있어야 성립하고, 테스트가
개발자 비밀에 의존하면 사람마다 결과가 갈린다. `DB_URL` 도 같은 이유로 실 DB 접근을
구조적으로 막는다.

## 1단계 — 기획 분석 (2026-08-02)

### 완결성 비평가가 실측으로 반박한 내 오류 3건

1. **AC-1 이 애초에 무효였다.** 내가 "지금 red"라고 잰 `env -u SECRET_SALT pytest` 는

   실제 변수는 환경변수가 아니라 **cwd** 다. 레포 루트에서는 242 passed —
   그 명령은 FR-4 를 관측하지 못한다.
2. **`get_session` 오버라이드로 DB 를 격리한다는 0단계 판정이 틀렸다.** DAO 3개 파일이
   `Depends(DB().get_db_session)` 를 쓴다. `get_session` 은 에이전트 라우터 2곳뿐이라
   컨트롤러 9개 라우트는 실 DB 로 간다 (실측: `no such table: KY_ATDC_L`).
3. **라우트 수 11/6 이 손으로 센 값이었다** — 비평가는 12/7 을 제시했다. 확정하지
   않고 4단계에서 실행으로 뽑기로 했다.

비평가는 그 밖에 앱 실결함 하나(`/admin/attendee/export` 라우트 가림 → 500),
`create_app()` 과 모듈 `app` 의 라우트 차이(16 vs 17, 401 핸들러 유무), 그리고
**검증 중 개발자 키로 실제 Groq 호출이 나간 사실**을 실측으로 보고했다.

### 사람 판정 3건

- `.env` 관측 → **conftest 강제 덮어쓰기.** 파일 부재 재현은 안 한다.
- `/admin/attendee/export` → **판정 번복 (2026-08-02, 사람 지적).** 처음에 나는 비평가의
  "500" 을 그대로 받아 "앱 실결함"으로 승격했다. **틀렸다 — export 는 동작한다.**
  실행으로 갈랐다:
  - `/admin/attendee/export/202601` → DAO 까지 도달 (내 프로브의 sqlite 에 테이블이
    없어서 멈춘 것이고, 라우팅·인증·컨트롤러는 정상)
  - `/admin/attendee/export` (날짜 없음) → `ValueError: 'export01'`
  그리고 **날짜 없는 경로를 부르는 곳이 레포에 없다** — 유일한 호출자는
  `app/template/admin_attendee.html:708` 의 `/admin/attendee/export/{{ cal_date_formatted }}`.
  즉 실결함이 아니라 **도달 불가한 등록(죽은 코드)** 이다.
  결과: **export 는 오라클에 포함된다** (AC-9). 날짜 없는 변형만 후속 과제로 적는다.
  - 교훈: 규칙 3(리뷰는 입력이고 판정은 내 것)을 내가 건너뛰었다. 비평가의 사실은
    맞았지만 프레이밍이 틀렸는데, 실사용 경로를 안 눌러보고 사람 판정까지 소모시켰다.
    **크리틱 출력도 실행으로 검증한 뒤에 승격한다.**
- admin 역할 → **공백이 아니라 의도된 설계.** 토큰은 로그인 이후에만 발급되고 무토큰은
  조회 전용. 코드로 확인: `KY_USER_L` 에 역할 컬럼 없음, `/attendee` 는 인증 안 검.
  한계가 아니라 검증 대상이 되어 FR-6·AC-7 로 승격.
  - 기대는 불변식을 명시: **`KY_USER_L` 에 관리자만 들어간다** — 코드가 아니라 데이터가
    지키는 성질이다.

세 번째에야 제대로 쟀다.

## 하네스 관측 (소유자는 모루 `docs/field/2026-07-31-port-2nd-cycle.md`)

이 실행은 그 문서의 **"다음 사이클에서 볼 것"** 이 지목한 바로 그 사이클이다 —
그때까지 파이프라인은 0회 실행이었다. 아래는 발생 순간의 1차 기록이고, 끝난 뒤
그 문서에 한 번에 옮긴다. **여기가 소유자가 아니다** — 모루 작업자는 이 파일을 안 본다.

### A. 실행의 부작용을 경고하는 규칙이 커널에 없다 (실측 1건)

커널은 여러 자리에서 **실행하라**고 지시한다 — `workflow.md` §판단의 실행 환원,
`07-review.md:66` "프로브 우선", `02-feature-analysis.md` §5 "추측 금지, 코드를 열어".
그런데 **그 실행이 바깥 세상을 건드릴 수 있다는 경고가 어디에도 없다.** 커널의
`외부 호출` 언급 4곳은 전부 *설계 대상 기능*의 타임아웃·상한 얘기지, *에이전트 자신의
프로브*가 아니다.

**실측**: 1단계 완결성 비평가가 지시대로 실행 검증을 하다가 `/agent/chat` 을 때렸고,
개발자의 실제 `GROQ_API_KEY` 로 **외부 유료 LLM 호출이 나갔다.** 2단계에서 재발하지
않은 유일한 이유는 내가 서브에이전트 프롬프트에 손으로 `GROQ_API_KEY=""` 경고를
넣었기 때문이다 — 하네스가 막은 게 아니다.

영향: 이 레포는 무료 티어라 비용이 작다. 메일 발송·결제·프로덕션 쓰기가 있는 레포에서
같은 지시를 따르면 결과가 다르다.

### B. 크리틱 지적을 "판정"이 아니라 "반영"하라고 쓰여 있다 (실측 1건)

`02-feature-analysis.md:67` — *"지적은 이 단계 안에서 **반영** 후 확정하고, 산출물에
'N개 반영' 또는 '지적 없음'으로 기록한다"*. 반영(apply)이지 판정(judge)이 아니다.
게이트 리뷰어에 대해서는 `AGENTS.md` 규칙 3 이 *"리뷰는 입력이고 판정은 내 것이다.
기각이 정상 결과다"* 라고 못 박는데, **파이프라인 단계 크리틱에는 그 짝이 없다.**

**실측**: 1단계 비평가가 `/admin/attendee/export` 를 "앱 실결함(500)"으로 냈고, 나는
검증 없이 그대로 사람 판정으로 승격했다. 사람이 "export 는 yyyymm 을 받는다, 동작한다"
고 지적해 다시 재보니 **실사용 경로는 정상**이고 날짜 없는 변형만 도달하지 않는 것이었다
(호출자 없음). 사실은 맞았지만 프레이밍이 틀렸고, 문구가 그 방향으로 민다.

### C. "다음 사이클에서 볼 것" 4개 항목에 대한 중간 답

| 그 문서의 질문 | 지금까지의 관측 |
|---|---|
| 3단계 설계 문서가 쓸 만한가, 종이인가 | 3단계 미도달 |
| 6단계 라우팅이 수렴하는가 | 미도달 |
| 7단계 독립 리뷰가 라운드 증식을 재현하는가 | 미도달 |

## 3단계 — 설계 (2026-08-02)

산출물: `03-design.md`

### 게이트 판정: 비게이트

6개 조건을 실측으로 순회해 전부 아니다. 두 개가 판단을 요구했다:

- **의존성 추가** — `httpx = "^0.27"`(:33), `uvicorn = "^0.29.0"`(:12) 둘 다 `pyproject.toml`
  에 **이미 선언돼 있다**. 실소켓 스모크를 넣어도 C-2 를 안 깬다.
- **고위험 경로** — `HIGH_RISK_PATH_RE` 는 `app/util/auth.py|db.py|config.py` 인데
  변경 파일 매치 0. 이 테스트들은 `auth.py` 를 **실행**하지만 **수정하지 않는다.**
  게이트는 변경 파일 경로에 거는 규칙이고, 커버리지가 0인 고위험 코드에 테스트를
  붙이는 것은 약화가 아니다.

→ best-of-4·Devil's Advocate 생략. 가정 대장은 유지.

### 설계에서 확정한 것

- **테스트 DB 는 파일 sqlite** (`:memory:` 아님). 실측 근거: in-memory 는 커넥션마다
  별개 DB 라 fixture 가 만든 테이블을 라우트가 못 본다 — 2단계 프로브가 이 함정에
  실제로 빠졌다.
- **커버리지 단언은 하한만**(`> 0`). 정확한 프레임 수를 박으면 라이브러리를 올릴 때
  깨진다 — 업그레이드를 막는 테스트는 오라클이 아니라 방해물이다. 이 오라클의 목적이
  업그레이드를 **가능하게** 하는 것이므로 자기모순이 된다.
- **고정할 현행 규칙 6개(R-1~R-6)** 를 명시했다. 이 작업은 앱 규칙을 만들지 않고
  기존 동작을 고정하므로, 무엇을 고정하는지가 곧 테스트의 계약이다.
- **분기 완전성에 구멍 1개를 남긴다**: R-6(LLM 키 없음 → error)의 음성 분기(키가
  있는 경우)는 외부 호출이라 테스트하지 않는다. 한계로 명시.

### 뮤테이션 검증이 오라클 구멍 하나를 뚫었다 (이번 단계의 수확)

9개 뮤테이션 중 8개는 잡혔고 **1개가 뚫렸다**: `app/dao/functions.py::get_password` 의
`.where(KyUserL.user_id == user_id)` 를 지워도 27개 테스트가 전부 초록이었다.
원인은 로그인 테스트가 전부 `admin` 으로만 두드리고 시드가 1명뿐이라, 쿼리가
사용자명을 무시해도 admin 의 해시가 돌아와 우연히 맞기 때문이다.

**계열이 나쁘다 — 인증 우회다.** 누가 그 쿼리를 리팩터하다 WHERE 를 흘려도 오라클이
아무 말을 안 한다.

메운 방법: **없는 사용자명 + 올바른 비밀번호**로 로그인해 거부되는지 보는 테스트 1개.
반증까지 했다 — WHERE 를 지우면 **그 테스트만 정확히 red**, 복구하면 23 통과.

### 독립 감사 판정: LOCK 보류 → 보강 후 해제

필수 2건 + minor 2건 전부 채택했다.

- **필수** `POST /admin/attendee` 유효 토큰 양성 — 이 앱의 **유일한 쓰기 라우트**인데
  읽기만 검증하고 있었다. 인가 경계가 가장 중요한 곳에 구멍.
- **필수** `GET /logout` — 라우트 스윕의 마지막 구멍. 쿠키를 실제로 지우는지까지 본다.
- **minor** 커버리지 프로브 요청의 상태를 단언 — 요청이 에러 경로로 빠져도 프레임은
  세어지므로, 안 보면 "정상 경로가 그 패키지를 탄다"가 아니라 "에러 페이지가 탄다"가 된다.
- **minor** 폼 양성 테스트 중복 제거 — 같은 요청을 두 파일이 소유하고 있었다.

감사가 내 의심 하나를 **기각**했다: 커버리지 하한(`>0`) 단언이 약하지 않냐는 것.
음성 대조(h11·cryptography·pymysql 이 0 임을 고정)가 짝이라 "목록만 늘리면 초록"이
안 된다. 받아들였다.

### LOCK 순서 오류 (내 실수, 정정함)

테스트를 커밋하기 **전에** LOCK 마커를 만들었다. 그러면 pre-commit `test-lock` 훅이
`tests/` 를 스테이징하는 모든 커밋을 막아 **테스트 자체를 커밋할 수 없다.**
`04-test-generation.md` §5 는 "테스트 코드를 확정하고 LOCK 마커를 생성해 커밋한다"
라고만 적어 순서를 명시하지 않는다 — 모루 쪽 후속 후보다.

사람 판정으로 순서를 바로잡았다: 마커 삭제 → 테스트 커밋 → 마커 재생성(스펙대로
3행 이상) → 마커 커밋. 그 시점에 마커도 테스트도 히스토리에 없었으므로 LOCK
윈도우가 시작되지 않았고, 우회가 아니라 순서 정정이다. `TEST_LOCK_OVERRIDE` 는
쓰지 않았다.

### 고친 것 두 건 (7단계 major)

**① h11 계측이 서버가 아니라 클라이언트를 세고 있었다.**
`sys.setprofile` 은 스레드 단위인데 인프로세스 uvicorn 과 httpx 가 **같은 이벤트
루프·같은 스레드**에서 돌아 둘의 프레임이 섞였다. 클라이언트에서 h11 을 제거하는 것이
해법이다 — `asyncio.open_connection` 으로 생 바이트를 쓴다. 더해서 `uvicorn.Config` 에
`http="h11"` 을 못 박았다(httptools 가 깔리면 uvicorn 이 그쪽을 쓰므로, 무엇이
파싱하는지를 우연에 맡기지 않는다).

**반증**: 클라이언트를 httpx 로 되돌리면 새 단언이 **503 프레임**을 잡아 red 를 낸다
(`counts["client"] == 0`). 즉 h11 계수가 서버 것임이 이제 실행으로 보장된다.

**② 고정 임시 DB 경로 → `mkdtemp`.**
**반증**: 고치기 전 동시 2프로세스가 3/3 충돌(`table "KY_ATDC_L" already exists`)했고,
지금은 둘 다 통과한다(5 passed / 6 passed).
