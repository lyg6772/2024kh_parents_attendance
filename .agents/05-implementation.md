# 5단계: 기능 구현

## Role

4단계에서 작성된 테스트를 통과시키는 코드를 구현한다.

## Input

- 4단계 산출물: 테스트 코드 (보호 중)
- 3단계 산출물: 설계 문서
- 0단계 산출물: 코드베이스 컨텍스트 + 재활용 목록

## Process

### 1. 구현 순서

설계 문서와 기능 의존관계에 따라 **의존 방향 순서**(다른 것이 의존하는 것부터)로
구현한다. 계층 구성·명칭은 타깃 레포 컨벤션 소유 (예: FastAPI라면
Model → Repository → Schema → Endpoint):

1. 데이터/도메인 계층
2. 데이터 접근 계층
3. 계약/스키마 계층
4. 진입점 (엔드포인트/핸들러)
5. 통합 배선 (라우팅 등록, export, 설정 추가, 예외 추가, 패키지 추가 등)

### 2. 재활용 규칙

0단계에서 파악한 재활용 가능 자산을 반드시 활용한다. 기존 코드와 동일한 기능을 새로 만들지 않는다.

### 3. 테스트 실행

각 파일 구현 후 관련 테스트를 실행하여 통과 여부를 확인한다.

### 4. 관측 계측 (설계 §3-2에 관측 설계가 있으면)

설계의 관측 설계(3단계 §3-2)에 정의된 로그·지표를 구현한다 — 특히 에러 경로.
설계에 없으면 임의로 추가하지 않는다 (관측도 설계 대상). 민감정보는 로그에서
제외한다.

### 5. 셀프 리팩터 (테스트 green 유지 — red-green-refactor의 refactor)

테스트가 전부 green이 된 뒤, 리뷰로 넘기기 전에 **작성자가** 리팩터 1패스를 돈다 —
중복 제거, 네이밍, 함수 크기. **테스트를 green으로 유지**하며(깨지면 리팩터가 틀린
것 → 되돌린다), 설계에 없는 추상화·유연성은 넣지 않는다(YAGNI — 7단계 과잉설계
렌즈가 잡는다). 이 다리를 건너뛰면 구조 문제를 7단계 리뷰어가 처음 발견해 리팩터
사이클을 낭비한다. 바꾼 것을 산출물에 기록한다 (없으면 "리팩터 불필요 — 사유").

## Output 템플릿

```markdown
## [5단계] 구현 산출물

### 입력
- 4단계 산출물: [테스트 파일 목록]
- 3단계 산출물: [설계 문서 참조]
- 0단계 산출물: [재활용 목록 참조]
- 누락 입력: [없으면 "없음"]

### 생성된 파일
| 파일 경로 | 목적 |
|-----------|------|
| [경로] | [목적] |

### 수정된 기존 파일
| 파일 경로 | 변경 내용 |
|-----------|----------|
| [경로] | [변경 내용] |

### 재활용한 기존 코드
| 재활용 대상 | 사용 위치 |
|------------|----------|
| [클래스/함수] | [어디에서 사용했는지] |

### 관측 계측 (§4)
- [구현한 로그/지표 목록 / 설계에 관측 없음 — N/A]

### 셀프 리팩터 (§5)
- [바꾼 것 목록 (green 유지 확인) / 리팩터 불필요 — 사유]

### 종료 조건
- [ ] 테스트가 모두 통과한다
- [ ] 설계의 통합 계획에 있는 기존 파일 수정을 모두 완료했다
- [ ] 재활용 가능한 기존 코드를 모두 활용했다
- [ ] 설계 §3-2 관측 항목을 구현했다 (설계에 없으면 N/A)
- [ ] 셀프 리팩터 1패스를 돌았고 테스트가 여전히 green이다 (불필요면 사유)

### 실패 시
- 테스트 실패 → 구현 코드 수정 (테스트 수정 X)
- 설계와 맞지 않는 부분 발견 → 사람에게 보고
```

## Rules

- **테스트 코드를 수정하지 않는다 (보호 중).** 에러 통과를 위해 테스트를 임의로 수정하지 않는다. 테스트가 통과하도록 구현 코드를 작성한다.
- 기존 코드 패턴을 따른다. `.agents/context/codebase-conventions.md` 참조.
- 중복 코드를 만들지 않는다. 기존 코드를 재활용한다.
- 설계 문서에 없는 코드를 임의로 추가하지 않는다.
- 설계의 통합 계획에 있는 기존 파일 수정을 누락하지 않는다.
- 구현 중 설계와 맞지 않는 부분을 발견하면 사람에게 보고한다. 임의로 설계를 변경하지 않는다.
- 타입 에러를 억제 프래그마·타입 회피로 무마하지 않는다 (예: `Any`, `# type: ignore`, `cast()`, `@ts-ignore`).
- **셀프 리팩터**: 테스트 green 상태에서 리팩터 1패스(중복/네이밍/함수 크기) 후 넘긴다. 리팩터 중 테스트가 깨지면 리팩터가 틀린 것 — 되돌린다. 설계에 없는 유연성은 넣지 않는다.
- **관측 계측**: 설계 §3-2의 로그·지표를 구현한다. 민감정보(PII·시크릿)는 로그에 남기지 않는다.
- **인라인 주석**: 비자명한 로직(우회, 성능 최적화, 외부 라이브러리 quirk 등)에는 "왜 이렇게 했는지" 주석을 단다. 자명한 코드에는 불필요한 주석을 달지 않는다.
- **결정 로그**: 이 단계 완료 시 생성/수정된 파일 목록, 재활용한 코드, 구현 중 발견한 이슈를 결정 로그에 append한다.
